# 路线图：从「读信」到「回信」

这份文档记录一个尚未实现、但决定了长期形态的想法。写下来是为了它不会在赶进度的过程中丢掉。

---

## 核心想法

现在的信是**单向**的：历史写给你。你读完，被触动，然后什么也做不了。

终极目标是把这条线闭合：

```
历史写信给你  →  你写回信  →  你的回信落到地图上  →  下一个人读到它
```

具体设想（来自项目发起人）：

> 让来自全球各地的任何人写下回信，或者他们自己的故事。用 Tripo 的图生图，把自己最有记忆点的一件物品上传上去，然后在地图上标出他们的位置。
>
> 链接世界上的每个人——我们每个人都在见证历史，也会成为历史。

**「我们每个人都在见证历史，也会成为历史」**——这其实是整个作品一直在说、但还没说出口的那句话。现在的信是「别人」成了历史；加上回信，「你」也在成为历史。

---

## 为什么它和现有作品是同一个东西

不是加功能，是补上作品的另一半。

| | 只有信 | 加上回信 |
|---|---|---|
| 用户角色 | 收到礼物的人 | **留下礼物的人** |
| 情绪落点 | 被理解 | 被理解，**并且留下痕迹** |
| 时间轴方向 | 过去 → 现在 | 过去 → 现在 → **未来** |

---

## 但它会改变产品的性质

必须说清楚，因为这不是小改动：

| | 现在 | 加上回信之后 |
|---|---|---|
| 内容来源 | 撰写、审校、锚定史实 | 用户生成，无法核证 |
| 运行方式 | 离线静态，零 API | 需要服务器、存储、审核 |
| 可信度主张 | **每条论断可追溯** | 这条不再成立 |
| 成本 | 一次性 960 积分 | 每件物件 60 积分 × 未知用户数 |

**最关键的是第三行。** 现在最有力的论点——「这不是 ChatGPT 套壳，因为有 466 条疆域规则和 126 个可核证事件在支撑」——建立在**所有内容都经过审校**之上。

混入未经核实的用户故事，这个论点的地基就松了。

**所以：用户内容必须是一个明确分离的层，不能和可核证的历史层混在一起。** 这不是技术洁癖，是这个作品能不能立住的问题。

---

## 已在代码中预留的接口

**`src/data/letters.ts` 已加 `LetterProvenance`**：

```ts
export type LetterProvenance = 'curated' | 'visitor';
```

现有 18 个 spec 全部标记为 `'curated'`。`'visitor'` 留给未来的回信。

代码注释里写明了约束：

> 那些条目绝不能被混入策展集——它们在构造上就是不可核证的，而整个作品的公信力建立在策展层保持可核证之上。这个功能落地时应该读自己的存储，而不是 `letterSpecs`。

**这样以后加回信不需要重构**，只需要新增一个数据源和一个 `provenance: 'visitor'` 的渲染分支。

---

## 三个必须正视的风险

### ① 成本无上限

60 积分一件物件，用户一多就是无底洞。除非：

- 改成「每人免费 N 次 + 超出付费」
- 或者回信阶段**不生成 3D**，只用文字（成本为零）

**建议：先做纯文字回信，验证情绪成立后再考虑 3D。**

### ② 3D 内容审核极难

文字可以过关键词，模型不行。这是真实的运营负担，不是技术问题。

### ③ 地图会被淹没

现在 16 件文物分布在 700 年跨度里，**清晰可读**。如果一天来 500 条回信，地图会变成一坨点云，「找到那一刻」的体验直接消失。

**这是最容易被低估的一点——稀缺性是当前体验的一部分。**

可能的解法（未验证）：
- 回信默认不显示，需要主动开关
- 按时间聚合成热力，而不是逐点显示
- 只在地图放大到一定层级时显示

---

## 建议的推进路径

### 第一步：最小闭环（约一天）

```
读完信  →  写一句回信  →  它作为一个点落在地球上
```

**不上传 3D、不联网、不做审核**，先存在本地。

这一步验证的是最核心的情绪：**你的话也留在了这条长河里。**

如果这一步成立，才继续往下走。如果不成立，省下后面所有的成本。

### 第二步：持久化与分享

回信存到服务端，生成一个可分享的链接。

### 第三步：Tripo 图生图

用户上传自己的物件照片 → 生成 3D → 附在回信里。

**这一步的成本和审核负担最重，应放在最后。**

### 第四步：真正的全球地图

每个人的回信在地图上可见。此时才需要认真设计「如何不被淹没」。

---

## 一句话总结

**这个方向是对的，而且它补上了作品唯一的缺口。但它是一个新产品，不是一个新功能——所以要先做最小闭环验证情绪，而不是一次性建完。**
