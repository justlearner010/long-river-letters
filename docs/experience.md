# 《来信》体验设计

这份文档说明三件事：项目怎么跑起来、我们希望用户经历什么、以及打开一封信时用户具体看到什么。

---

## 一、项目怎么开始

```bash
npm install
npm run dev          # 开发服务器，http://localhost:5173（热更新）
```

生产构建与本地预览：

```bash
npm run build        # 校验数据 → 类型检查 → 打包
npx vite preview     # 构建产物预览，http://localhost:4173
```

其他命令：

| 命令 | 作用 |
|---|---|
| `npm test` | 全部单元与集成测试 |
| `npm run validate` | 只校验数据一致性（构建时也会跑） |
| `npm run verify:models` | 检查 3D 物件是否符合规格 |
| `npm run generate:letters` | 生成信件正文（**需要 `ANTHROPIC_API_KEY`**） |

> **当前状态**：信件正文尚未生成。点进信件会看到人物小传与史料依据，正文部分提示尚未生成。跑一次 `generate:letters` 即可补全。

## 二、我们希望用户体验到什么

### 一句话

**不是安慰，是陪伴。**

### 用户带着什么来

深夜刷手机时那种感觉：一切都在崩坏，从来没人经历过这些，我们是特别倒霉的一代。

### 我们想让他带走什么

**「有人经历过。而且他们当时也不知道结局。」**

这是整个作品唯一的论点。不是「历史会重演」，不是「一切都会好起来」——是**处境上的共鸣**。历史上真的有人在瘟疫、封锁、战争里写下过字，而且他们同样不知道这一切会怎么结束。

**信里不会说「会好起来的」。** 信里会说：我在这里，这是我看见的，这是我当时还不知道的。

### 四个焦虑，四种处境

| 焦虑 | 用户心里的问题 | 信件回答的方式 |
|---|---|---|
| 战争 | 战争会不会烧到我这里 | 一个奥匈军官在 1914 年开赴前线，他以为很快就回来 |
| 瘟疫 | 会不会轮到我和家人 | 一个罗马书记记录瘟疫中的祈愿与无力 |
| 贸易封锁 | 世界会不会裂成两半 | 一个阿姆斯特丹商人发现海路一断，秤上就没有东西可称 |
| 技术冲击 | 我的手艺还值不值得学 | 一个排字工看见机器一天排出的字比他一年还多 |

### 三段情绪曲线

```
点下「战争」
   ↓
  「它在问我」          ← 一句安静的问题，不是四个大按钮
   ↓
   震动                  ← 读到一个具体的人在具体的一天做的事
   ↓
  「原来真的有人经历过」  ← 地图在背后倒放 700 年，停在那一刻
   ↓
  「这不是比喻」          ← 每条因果链都能点开，跳回真实事件记录
   ↓
  「这是我的了」          ← 信可以带走
```

**关键设计判断**：信必须先出现，地图在后。

原本的设计是「选焦虑 → 地图倒放 → 信展开」。这个顺序错了——展廊里访客只有 60 秒，先播 8 秒动画，他还没读到信就走了。**情绪钩子必须第一时间出现，地图是追认，不是前戏。**

### 我们不要的东西

- **不要打字机效果**。中文逐字打字一封 500 字的信要 20 秒，强迫用户等动画。淡入更快、更克制、更像纸。
- **不要四个大按钮**。菜单不会让人产生情绪，提问会。
- **不要「历史总是惊人地相似」这类话**。那是廉价的、可以被反驳的论断。我们只呈现处境。
- **不要因果断言**。历史因果是有争议的，每条链都标注为「一种理解视角」。

## 三、打开信件，用户看到什么

### 五幕结构（共约 55 秒，一个展廊访客的停留窗口）

| 幕 | 时长 | 用户做什么 | 看到什么 |
|---|---|---|---|
| 1 恐惧 | 5 秒 | 点一个词 | 全屏安静下来，一句提问 |
| 2 来信 | 15 秒 | 读 | **信纸展开，字句逐段浮现**（情绪峰值） |
| 3 纵身 | 10 秒 | 不做任何事 | 地图在背后倒放 700 年，停在锚点年份 |
| 4 回响 | 20 秒 | 点因果链 | 每一跳跳回地图该年，展开当时的事件 |
| 5 带走 | 5 秒 | 下载 | 信存成图片 |

### 第一幕：提问

```
┌────────────────────────────────────────────┐
│                                            │
│                                            │
│      2026 年的你，在担心什么？              │
│                                            │
│      [ 战争 ]   瘟疫   封锁   技术          │
│                                            │
│                                            │
└────────────────────────────────────────────┘
```

一行安静的文字问题，四个词作为**可点击文本**，不是按钮块。第一个词用强调色，暗示「从这里开始」。这一屏要像呼吸，不像仪表盘。

### 第二幕：信件展开（最重要的一屏）

```
┌──────────────────────────────────────────────────────────┐
│  ← 返回        奥匈帝国 · 一战爆发 · 公元 1914 年  [返回] │
├──────────────────────────────────────────────────────────┤
│                                                          │
│   ┌────────────────────────────────┐   ╭────────────╮   │
│   │ 卡尔·冯·韦尔奇 [史有其人]       │   │            │   │
│   │                                │   │   3D 物件   │   │
│   │ 致 2026 年的你：                │   │   可旋转    │   │
│   │                                │   │            │   │
│   │ 我写下这些字的时候，萨拉热窝    │   │  民用防毒   │   │
│   │ 的枪声已经过去了六天……         │   │    面具     │   │
│   │                                │   ╰────────────╯   │
│   │                    —— 韦尔奇    │                    │
│   │ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  │   ┌──────────────┐ │
│   │ 本信基于以下已记录史实：        │   │ 史料依据脚注  │ │
│   │  · 1914 · 萨拉热窝事件与一战爆发│   │ 必须与信同时  │ │
│   │  · 起因：民族主义与同盟体系…    │   │ 可见          │ │
│   │  · 《韦尔奇战时日记》1914—1916  │   └──────────────┘ │
│   └────────────────────────────────┘                    │
├──────────────────────────────────────────────────────────┤
│ 从那一刻到今天                                           │
│ [1914 萨拉热窝]→[1939 德苏条约]→[1941 巴巴罗萨]→[1942…] │
└──────────────────────────────────────────────────────────┘
```

**四个必须同时可见的元素**：

1. **发信人身份**——名字 + `史有其人` 或 `时代亲历者（据史料重构）` 标签。这个区分是硬要求：代码库里没有任何人物数据可校验，所以具名人物必须真有史料依据。
2. **信纸本体**——刻意区别于 UI：字号 17px（UI 是 12–14px）、行高 1.9（UI 是 1.35–1.7）、衬线字体、边缘轻微不规则。
3. **3D 物件**——不是装饰。它是「这个人真的碰过东西」的物证。缓慢自转，约 30 秒一圈。
4. **史料脚注**——**这是「不是 ChatGPT 套壳」的视觉证据**，必须与信同时可见，不能折叠。

### 第三幕：地图倒放

信纸不消失，而是**稍微缩小、左移**，右侧和背景露出地球。地图在约 1.5 秒内倒放 700 年，停在锚点年份。

倒放结束后地图不做任何事——它是背景，是氛围。用户此刻在读信，地图的存在只是让他余光看到「世界在变」。

### 第四幕：因果链

信末一条水平链，从锚点事件指向今天。**每一跳都可点击**：

- 点击 → 地图跳到那一年，打开该事件的详情面板
- 再点一次 → 收起

**这是全场最能证明技术深度的地方**：因果链的每一跳都指向真实的事件记录（126 个手工核对的事件 + 466 条疆域规则），不是 AI 生成的连接。

### 第五幕：带走

「存下这封信」→ 导出 PNG。

**这一屏是可裁的**——如果时间不够，砍掉它，不要为了它挤占信本身的质量。

## 四、边界与判断

### 疆域表述

地图基于**现代国家轮廓**按历史控制者着色，主要帝国边界以近似覆盖表达。争议地带保持中性描述，具体来源与精度在数据文件中逐条标记。

古代疆域争议远大于现代，因此规则中大量使用低优先级 + 不确定性注释，而非断言。**宁可显示得保守，不可显示得确定。**

### 人物真实性

代码库中**没有任何结构化的人物数据**——人名只零散出现在叙述字符串里。因此：

- `historical`：有史料依据的具名人物，附带出处
- `archetypal`：据史料重构的**时代亲历者**，不具名，UI 上明确标注

**不允许编造具名历史人物。** 无法在史料中落实的名字，一律用「一位无名书记」这样的身份。

### 因果表述

每条因果链标注为**一种理解视角**，不是定论。历史因果在学界有争议，把它说成必然既不准，也是一种谎言。

## 五、演示脚本

### 场景 A：展廊路过（60 秒）

只走第 1–2 幕。**不要演示地图倒放**——太慢。让他读一封信，读到他抬头。

预案：预置一封最强收益的信，一键直达。

### 场景 B：现场讲解（3 分钟）

走完五幕，但在第四幕重点展开「为什么这不是 ChatGPT 套壳」——因果链每一跳都指向真实事件记录。

### 场景 C：现场联网演示（高风险）

预生成保底 + 现场生成作为「追问」。**赛前必须实测网络与额度。**
