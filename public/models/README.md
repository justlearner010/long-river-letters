# Artifact models

Sixteen 3D artifact models (`.glb`) live here, rendered with
`@google/model-viewer`. They are generated by Tripo3D and then **must** be
run through the optimization pipeline below before being committed.

## Spec

Every file in this directory must satisfy all of the following. Run
`npm run verify:models` to check; it exits non-zero if any file fails, so it
can gate a build.

| Metric | Requirement | Why |
| --- | --- | --- |
| File size | ≤ 2 MB | 16 models ship with the app; total page weight matters |
| Triangles | ≤ 30,000 | Hero prop viewed close up; more is wasted |
| Textures | ≤ 1024 × 1024 | 4096² costs 16× the area for no visible gain |
| `metallicFactor` | `0`, or `1` for the four metal artifacts | See "Metalness" below |
| Bounding box | longest edge `1.0` (± 0.05) | Normalized size across all artifacts |
| `normalTexture.scale` | ≤ 0.6 | Keeps baked normal maps weak |
| Animations / skins | none | Static artifacts |
| `extensionsUsed` | `KHR_mesh_quantization` only | See "The Draco trap" below |

### Metalness

The four genuinely metal artifacts get `metallicFactor: 1`:

- `lead-customs-seal.glb`
- `spanish-silver-coin.glb`
- `metal-movable-type.glb`
- `brass-trade-weight.glb`

**Everything else is `metallicFactor: 0`** — terracotta, wood, stone, fabric,
rubber, jade, porcelain.

This matters because Tripo3D drives metalness from the ORM texture's blue
channel but leaves the base `metallicFactor` at its glTF default of `1.0`. For
terracotta that renders as chrome. Note that the default applies when the
property is *absent*, so a missing `metallicFactor` is also a bug, not a
neutral value.

The authoritative list is `src/data/model-manifest.ts`. Both scripts read it.

## Optimization pipeline

Tripo3D output is far above spec — the first test model measured 53.75 MB /
1,908,837 triangles / 3 × 4096² JPEG textures, i.e. 64× the triangle budget.
Compress every file as it comes out of Tripo:

```bash
npx @gltf-transform/cli optimize input.glb output.glb \
  --simplify-ratio 0.02 \
  --texture-size 1024 \
  --compress quantize
```

> **`--compress quantize`, not `--compress quantization`.** Verified against
> `@gltf-transform/cli@4.5.0`. The option's validator is
> `['draco', 'meshopt', 'quantize', false]`; passing `quantization` aborts with
> `Invalid value for option --compress. Expected one of 'draco', 'meshopt',
> 'quantize', 'false', but got "quantization".`

`--simplify-ratio 0.02` is aggressive (keeps ~2% of vertices) and is sized for
Tripo's ~1.9M-triangle output landing around 38k — check the result with
`npm run verify:models` and raise the ratio if a model looks too coarse.
`optimize` also runs `weld`, `prune` and `textureCompress` automatically.

### The Draco trap

**Do not let Draco anywhere near these files.** `@google/model-viewer` cannot
load `KHR_draco_mesh_compression` without a decoder that it does not fetch by
default. Using Draco means adding a runtime network dependency on a decoder
CDN, which breaks the app's offline-capable guarantee — and it fails at
runtime in the browser, not at build time, so it is easy to ship by accident.

`KHR_mesh_quantization` is the correct choice: it stores vertex attributes as
plain 16-bit integers with a node scale, requires **no decoder**, and is
natively supported by model-viewer. `EXT_meshopt_compression` has the same
problem as Draco and is likewise not allowed.

`scripts/verify-models.ts` treats Draco as a hard error, scanning
`extensionsUsed`, `extensionsRequired`, and every `primitive.extensions`. For
independent confirmation that the trap is real, ask `@gltf-transform/core` to
read a Draco file:

```
Error: Missing required extension, "KHR_draco_mesh_compression".
```

## Repairing metalness and normal scale

`optimize` cannot fix material factors, because they are per-object semantic
decisions it has no way to know. Use the fixer:

```bash
npm run fix:models            # dry run: prints what would change
npm run fix:models -- --write # apply in place
npm run verify:models         # confirm
```

It rewrites only the GLB's JSON chunk, copying the BIN chunk byte-for-byte and
recomputing the header length. `bufferView.byteOffset` values are relative to
the start of the BIN payload, so relocating the BIN chunk within the file
invalidates nothing.

The fixer repairs exactly two things:

1. `metallicFactor`, per `src/data/model-manifest.ts`
2. `normalTexture.scale`, clamped to `≤ 0.6`

It does **not** fix size, triangle count or texture resolution — those need
`optimize`. A file that only the fixer has touched will still fail
verification if it is oversized.

`optimize` also resets the material factors it can infer from textures, so run
the pipeline **first** and the fixer **second**:

```bash
npx @gltf-transform/cli optimize raw.glb public/models/artifact.glb \
  --simplify-ratio 0.02 --texture-size 1024 --compress quantize
npm run fix:models -- --write
npm run verify:models
```

Files not listed in the manifest are skipped with an error rather than guessed
at, since the correct `metallicFactor` cannot be derived from the file itself.

## Files

`.glb` binaries are **not** committed. Only this README and `.gitkeep` are
tracked, so the directory exists for the dev server path `/models/*.glb`.
